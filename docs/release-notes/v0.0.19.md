## 修复

- **修复 GitHub 搜索已生效却报超时**：直接打开搜索页后输入并回车时，GitHub 会在同一个文档中更新 URL。此前 App 只等待新文档 GET，即使结果已出现也会等到超时。本版确认原生 Enter 后的同源、同文档 URL 跳转，不再把这条路径误判为未确认操作。
- **不重载、不重复提交**：确认同文档跳转时保留原页面、标签、授权和桌面尺寸，不重新 GET、不再按 Enter。旧引用失效，代理须用新的快照检查结果。返回“导航已观测”不代表网站数据已全部加载，也不保证业务操作成功；只有 DOM 改变而无 URL 跳转的情况仍保留未确认状态。
- **收尾预算与权限边界**：提交工作在传输硬截止前停止，预留时间清理并返回结果，避免正常的未确认结果被外层超时抢成 `DEADLINE`。GET 接续在创建和配置页面之后再次检查截止时间，自动授权也受同一截止限制。隐藏、接管、取消和身份变化后的迟到回调不能完成旧提交。

- 1006 项 JVM 测试、292 项 Node 测试通过，Android lint 无错误；另有 1 项可选上游源码检查跳过。最终模拟器整组 23 项回归通过，本地插件传输、重启和冷启动通过。
- 真实 GitHub 搜索页前后对照：手机和电脑模式均收到一次可信原生 Enter 按下/抬起，保留同一页面和文档。修复前约 20 秒返回未确认；修复后手机约 1.21 秒、电脑约 1.34 秒确认导航，控制权保留。真实模型首次操作成功，随后快照读回搜索结果，未重试。

## Fixed

- **GitHub search no longer times out after succeeding**: submitting from the search page can update the URL inside the same document. The app previously waited only for a new main-frame GET and timed out even when results were visible. It now verifies a same-origin, same-document URL navigation after the native Enter.
- **No reload or duplicate submission**: the same-document path keeps the view, tab, grant and desktop size, without another GET or Enter. Old refs expire; the agent must inspect a fresh snapshot. A navigation-observed reply is not a guarantee that site data finished loading or that a business operation succeeded. DOM-only changes without URL navigation remain unconfirmed.
- **Cleanup budget and authority fences**: submit work stops before the transport's hard deadline, leaving time to clean up and return a domain result rather than racing into `DEADLINE`. GET continuation rechecks its deadline after page creation/configuration, and automatic grants share that deadline. Late callbacks after hide, takeover, cancellation or identity changes cannot complete an old submit.
