## 修复与改进

- **直接在通知中输入**：文本问题不再跳转到原生表单页面。单字段直接回复，多字段逐项暂存，最后一次提交整张答案；支持 OpenCode question 的 `custom: true` 自定义输入。
- **同机配对交互**：参考 Shizuku 的通知内输入方式，在系统无线调试配对弹窗仍打开时填写信息，不因切换 Activity 中断配对。可返回修改、跳过可选项或划掉通知取消本地填写。
- **安全恢复**：旧动作不能覆盖新问题；草稿丢失后从第一项重新填写。发送中提供“检查状态”，不会自动重发；划掉通知后不再被迟到结果恢复。已填答案不回显到通知正文或回复历史。
- **请求取消**：通知输入具有整体执行预算，HTTP 随取消及时终止；每次请求隔离 Cookie，避免迟到响应污染新服务会话。

## 验证与边界

- 1303 项 JVM 测试、Android lint、Debug/Release/androidTest 构建通过。

## Fixes and improvements

- **Reply inside notifications**: text questions no longer open the native form screen. Single fields accept a direct reply; multiple fields are staged locally and submitted together after the last field. OpenCode question fields with `custom: true` are supported.
- **Same-device pairing interaction**: following Shizuku's inline-reply approach, answers can be entered while Android's wireless-debugging pairing dialog stays open. Go back to edit, skip optional fields, or dismiss the notification to discard the local draft.
- **Safe recovery**: stale actions cannot replace newer questions. Lost drafts restart at the first field. Sending notifications offer Check status without automatic resubmission, and late results do not resurrect dismissed notifications. Answers are not echoed into notification bodies or reply history.
- **Request cancellation**: inline actions have a total execution budget and cancel their HTTP calls. Per-call cookies prevent late responses from contaminating a newer server session.

## Verification and limitations

- ADB was installed only in the isolated test guest. This release does not automatically install ADB or discover pairing ports. No arm64 hardware, OEM SystemUI, or model-generated pairing conversation was validated. See `docs/testing-inline-notification-pairing.md`.
