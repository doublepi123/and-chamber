# v0.0.33 — 页面一直在变也能点

> Taps work on pages that keep changing.

## 修复

- **页面内容变化不再拦住点击**：以前读屏后，页面上任何文字或位置变了（倒计时、轮播图、价格、角标），点击都会被拒绝，返回 `WINDOW_CHANGED`。电商这类页面几乎一直在变，导致点击几乎总是失败。现在只要求仍是同一个真实窗口（同一个界面、同一个应用、方向和屏幕尺寸不变），页面内容的正常变化不再拦住操作。
- **按元素点击仍会核对目标**：通过元素编号点击时，要求读屏时的那个元素仍在原来的位置。元素已经消失或移动时，仍然拒绝，避免点错。
- **仍然会拒绝的情况**：切换到新界面或弹出新窗口、切到别的应用、旋转屏幕、屏幕尺寸变化。截图、浮窗遮挡和授权检查不变。

## 验证范围

- 模拟器（API 35 / x86_64）上运行了真实驱动的端到端检查：同一窗口内容变化后，截图和点击可以继续；元素不在原位置的点击被拒绝；新界面仍会让旧读屏失效；返回和输入正常。
- 2,075 项 JVM 测试、361 项 Node 测试（360 项通过，1 项为原有跳过）通过，lint 和 debug/AndroidTest 打包通过。
- 还没在真机上的电商页面复测这一版。

## Fixes

- **Content changes no longer block taps**: any change in text or position after a snapshot (countdowns, carousels, prices, badges) used to refuse an action with `WINDOW_CHANGED`, so constantly updating pages could almost never be tapped. Actions now require only the same real window (same activity, app, rotation and display size).
- **A tap by element still checks its target**: the observed element must still be live at exactly the same bounds; a moved or missing element is refused.
- **Still refused**: a new activity or dialog window, another app, rotation or a display-size change. Capture, overlay and authorization checks are unchanged.

## Verification scope

- Real-driver end-to-end checks on an API 35 / x86_64 emulator: capture and taps continue after a same-window content change, a tap whose element is not at its observed bounds is refused, a new activity still invalidates the old snapshot, and back/input work.
- 2,075 JVM and 361 Node tests (360 passed plus one existing skip) passed, with lint and debug/AndroidTest packaging.
- This build has not yet been re-tested on a real phone with a shopping page.
