## 修复

- **平板全屏与输入法**：电脑版网页现在会等比适配可用区域，不再被固定为小块居中显示。全屏中弹出输入法时保持网页比例，将触点附近的输入区域移到键盘上方；收起后恢复布局，不重建网页或重复提交。键盘遮住部分页面时，整页截图仍会明确拒绝。
- **完整页面截图**：修正浮点缩放取整可能让画布略微超出容器、从而误触截图保护的问题。按实际提交的显示帧计算截图边界，未放宽裁切、窗口或相邻页面泄露保护。
- **结果链接导航**：代理点击普通同标签页 HTTPS 链接后，必须等到匹配的原生 GET、新文档与控制权确认后才返回导航成功，不再只点中元素却留在原页。点击和回车共用调用方预算，不自动重发；POST、下载、新窗口和任意脚本导航没有因此放开。
- **重载与回调隔离**：模式重载先建立新加载身份和旧文档排除屏障，再变更配置，避免迟到的旧文档探针误伤新页面。旧操作的回调不能污染新操作；未应用的视口请求不再虚报成功。
- **首次 HTTPS 跳转**：首次受控 GET 的合法 HTTPS 重定向不再被误判为需要重新打开页面。
- **首屏空白回调**：首次受控页面尚未开始、尚无已接受文档且没有错误时，缺少文档标识的探针只等待，不撤销页面。实际文档开始后及已接受文档的身份检查仍严格执行，URL 策略未放宽。

## Fixed

- **Tablet full screen and the keyboard**: desktop pages now fit the available area proportionally instead of staying small and centered. Opening the keyboard in full screen keeps the page scale and pans toward the tapped input; closing it restores the layout without rebuilding the page or repeating a submission. Full-page capture remains refused while the keyboard clips the page.
- **Full-page capture**: fixed floating-point scale rounding that could slightly overflow the container and incorrectly refuse capture. Capture uses the committed presentation's bounds; clipping, window and neighboring-content protections are unchanged.
- **Result-link navigation**: an agent click on an ordinary same-tab HTTPS link now waits for the matching native GET, new document and confirmed grant instead of merely activating the element. Click and Enter continuation share the caller's budget and are never replayed automatically. This does not enable POST, downloads, new windows or arbitrary script navigation.
- **Reload and callback isolation**: layout reloads reserve a new load identity and exclude the previous document before configuring the page. Late old-document probes cannot invalidate the new page, old-action callbacks cannot poison a newer action, and unapplied viewport requests no longer claim success.
- **Initial HTTPS redirects**: a permitted HTTPS redirect from the first controlled GET no longer incorrectly requires reopening the page.
- **Initial blank callbacks**: a missing-witness probe only waits while a controlled first load has not started, no document has been accepted and no page error exists. Identity checks after a document starts or is accepted remain strict; URL policy is unchanged.

- 1080 JVM tests and Android lint pass. Direct Node checks pass 35 tests with one optional check skipped; all 72 Python checks pass.
- The final x86_64 emulator run passes 25 formal browser regressions plus two separately reported Enter-budget diagnostics. Two independent combined runs each pass all six real-keyboard/public-site scenarios, including search, Enter, result links, scrolling, capture, non-submitted form entry, viewport changes and authority transitions.
- Full-screen and real-keyboard presentation were manually checked on an arm64 tablet. This is not physical-device instrumentation, capture-tool or plugin/runtime/LLM end-to-end evidence.
- After the initial-blank fix, 21 focused emulator regressions covering initial callbacks, submission, authority recovery and the keyboard pass. Reopening the previously blank public entry on the tablet restored visible content and agent control.
- **Still tracked**: keyboard Next, script-driven focus and mouse-mode input panning are not covered. One earlier search-submit refusal and the historical intermittent Enter investigation remain unclassified. Passing controls and final combined runs do not claim to explain or fix every intermittent submission issue. Login, CAPTCHA, payment and actual form submission are outside this acceptance run.
