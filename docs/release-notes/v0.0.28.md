## 新增与改进

- **自动发现本机无线调试端口**：通过有界的前台发现服务使用 Android 官方的 `_adb-tls-pairing._tcp` / `_adb-tls-connect._tcp`，只接受本机地址，并用回环 bind 监听验证（仅 `EADDRINUSE` 视为端口已被本机监听）。主流程只需输入系统配对框中的六位码，配对成功后自动重新发现并建立一次 TLS 连接；已配对用户可使用“查找并连接”。原有主机/端口输入保留为折叠的手动回退。取消、完成或五分钟边界会停止服务、发现和短时 MulticastLock；不扫描端口、不读取 shell 属性，也不新增附近设备/定位运行时权限。
- **显式永久有效期**：配置有效期和每任务时限均可明确选择“永久”，默认值仍是有限时长。内部只使用同一个永久 sentinel，工具状态以 `leasePermanent` 和无倒计时表示；永久不会移除停止、锁屏、断线、runtime 变化、进程结束、容量或单次调用超时边界。有限 scope 内的永久任务仍受 scope 结束时间限制。永久 scope 只是配置，不会在重启后恢复 grant、观察或任务路由。
- **当前任务问题与通知浮窗**：浮窗可显示当前任务的通知问题或普通通知，来源仅为本地 stdout，并对当前任务/会话/launch/表单 schema 做校验。Ready 的单选问题提供选项和明确 Send，发送后同一模型 turn 继续；Permission 独立保留原通知入口，复杂表单打开聊天，Unknown 不会自动重发。普通 Ready/Error/Goal/RestartInterrupted 通知有界展示。发送前先收起浮窗，只有同一任务和答案身份失败时才只读展开，避免遮挡目标。
- **平板跨任务交接修正**：包含此前平板跨任务交接的竞态修正；该修正不扩大新功能在平板上的验证范围。

## 验证与重要边界

- 本轮新增的自动端口、永久配置和问题浮窗三项仅在 **API 35 / x86_64 模拟器**验证。全新独立测试包只通过真实 SystemUI RemoteInput 输入六位码，并自动完成 TLS 连接；永久 scope 保存并重启后保留，实际 lease 显示正确；真实内置单题（`q0`、`custom:true`）在浮窗选择 **Tap Save** 并 Send 后返回 HTTP 204，同一模型 turn 继续且 Saved 计数为 1，不需要额外提示。首次 Unknown 的原因未确定，未重发该答案；最终两次无诊断日志构建的端到端运行通过。配置重启保留和接管撤权也在该环境检查。
- 此前 API 37 / arm64 平板的通过记录仅覆盖基础流程；用户明确暂不复测平板，本轮新功能未在平板验证。详见 `docs/testing-phone-control.md` 与 `docs/testing-phone-overlay.md`。**模型端仍是确定性协议夹具，不代表真实模型推理或自主规划能力。**
- 发布前全量检查通过：1,948 项 JVM，0 失败、错误或跳过；Node 359 项（358 通过、1 项既有跳过）；Python 72 项通过。Android lint、debug 和 AndroidTest APK 构建通过，保留既有 lint warnings/information；本轮未新增设备 instrumentation 执行。发布流程另行构建并校验签名 APK。
- 首次 Unknown 的具体原因尚未确定，因此不声称已消除所有发送失败或所有浮窗状态问题。厂商系统、API 37 新功能、TalkBack、多窗口差异和真实模型推理仍未验证。
- 仅适用于可信的整个本机 runtime。同 UID 插件/子进程不构成强隔离；ADB 配对具有设备级权限，目标应用检查不是 OS 沙箱。授权观察可能发送给当前模型服务商。当前输入仍仅支持声明的 ASCII 子集，不支持 Unicode/密码输入或自动提交。

## Features and improvements

- **Automatic local wireless-debugging discovery:** a bounded foreground discovery service uses Android's official `_adb-tls-pairing._tcp` / `_adb-tls-connect._tcp`, accepts only this phone's own numeric addresses, and confirms a single resolved port with a loopback bind occupancy check (only `EADDRINUSE` counts). The main flow asks only for the six-digit code, then starts one automatic TLS connect after a fresh connect discovery; already-paired users can use **Find and connect**. The old host/port entry remains as a folded manual fallback. Cancel, completion or the five-minute bound stops the service, discovery and short-lived MulticastLock; it does not scan ports, read shell properties or add nearby-device/location runtime permission.
- **Explicit permanent durations:** both the standing window and per-task limit can be explicitly **Permanent**, while finite defaults are unchanged. The native side uses one sentinel; the tool reports `leasePermanent` with no countdown. Permanent never removes stop, screen-lock, disconnect, runtime-change, process-end, capacity or per-call timeout boundaries. A permanent per-task choice inside a finite scope is still bounded by the scope end. A permanent scope is configuration only and restores no grant, observation or task route after restart.
- **Current-task question and notice overlay:** the floating surface can show the current task's notification question or plain notice from local stdout only, fenced by task/session/launch/form schema. A Ready single-choice question exposes choices and an explicit Send; a successful answer continues the same model turn. Permission keeps its original notification entry, complex forms open the chat, and Unknown is never resent automatically. Ready/Error/Goal/RestartInterrupted notices are bounded. The panel collapses before sending and reopens read-only only for the same task and answer identity after a failure, so it does not keep covering the target.
- **Tablet cross-task handoff fix:** includes the earlier tablet cross-task handoff race fix. That fix does not expand the new-feature evidence on the tablet.

## Verification and limitations

- The new auto-port, permanent-duration and question-overlay paths were verified only on the **API 35 / x86_64 emulator**. A fresh independent test package accepted only a six-digit code entered through real SystemUI RemoteInput and completed the automatic TLS connect. A permanent scope survived save/restart with the real lease shown as permanent. A real built-in question (`q0`, `custom:true`) selected **Tap Save** and Send in the overlay, returned HTTP 204, continued the same model turn, kept the Saved count at exactly one and required no extra prompt. The cause of the first Unknown outcome remains undetermined; that answer was not resent. The final end-to-end flow passed twice on builds without diagnostic logging. Configuration-restart retention and take-over revocation were also checked there.
- The earlier API 37 / arm64 tablet pass covers only the basic flows. The user deferred tablet retesting; the new features are not verified on that device. See `docs/testing-phone-control.md` and `docs/testing-phone-overlay.md`. **The model remains a deterministic protocol fixture, not real reasoning or autonomous planning.**
- Pre-release full checks passed: 1,948 JVM tests with no failures, errors or skips; 359 Node tests (358 passed plus one existing skip); and 72 Python tests. Android lint, debug and AndroidTest APK packaging passed with existing lint warnings/information. No new device instrumentation was executed. The release workflow separately builds and verifies the signed APK.
- The cause of the first Unknown outcome is still undetermined, so this release does not claim that every send failure or overlay state issue is eliminated. Physical/vendor systems, API 37 new features, TalkBack, multi-window differences and real-model reasoning remain unverified.
- Trust the entire local runtime. Same-UID plugins/subprocesses are not strongly isolated; ADB pairing has device-level authority, and target checks are not an OS sandbox. Authorized observations can reach the configured model provider. Input remains limited to the declared ASCII subset, with no Unicode/password entry or automatic submission.
