## 修复与改进

- **启动观测不再由下一次读取掩盖首因**：旧启动观测只有 5 秒，而 AOSP `uiautomator` 的 idle 等待是 1 秒 quiet / 10 秒全局上限。忙目标上 App 自己的读 watchdog 先到期并关闭本地连接，随后一次 Observe 只看到 `NOT_CONNECTED`，首个真实原因被覆盖。现在启动/续接观测共享一个最多 15 秒的预算（包含 overlay surface 等待和真实剩余时间），fatal 结果不再盲重试；固定 `HIERARCHY_NOT_IDLE` / `READ_TIMEOUT` 及 `startFailureStage` 保留首个 typed 原因。普通调用的 15 秒上限没有被延长；driver 只在原预算内预留不超过 500 ms 的上报余量，外层先到期仍可是普通 `DEADLINE`。
- **忙层级与读超时按固定原因安全拒绝**：层级输出只有在整体 trim 后精确等于 AOSP 固定 idle 句时才是 `HIERARCHY_NOT_IDLE`；合法 XML 里出现同样文字不会被误标，partial/invalid/unknown 仍 fail-closed。`READ_TIMEOUT` 覆盖 read-service 的 `open` 与 `read`：表示该事务已放弃 exact connection，core 在同一次 execute 内发布 logical disconnect/revoke，保留 unknown，并用 connection owner fence 保护更新连接；不声称物理 socket close 已完成。原有 hard watchdog 仍会关闭 stream 和 connection，没有 stream-only 保活。
- **启动窗口的 null 字段只做有界重试**：窗口管理器输出中只有完整官方字段行 `mCurrentFocus=null` 或 `mFocusedApp=null` 且对应 match 缺失时，才归类为 `NOT_READY` 并映射为 `WINDOW_CHANGED`，且只在既有 shared startup 预算内重试明确 window transition。缺字段、截断、超出 cap、坏 package/activity 或未知格式仍 fail-closed；不产 partial window/target nodes，capture/mutation 的两侧窗口核验以及 sensitive/overlay/target 安全都不放宽。
- **取消与未知结果语义不变**：grant 之后的 cancel 仍精确回滚该 epoch/task 并传播原 `Cancelled`，不会影响更新的 owner；`touched`/`afterWrite` 的结果仍是 `UNKNOWN`，不会自动重放。旧的 scope 与 person resume 路径保持不变。
- **bounded-busy 钩子只在独立 test APK**：默认值为 0，不新增权限或服务，也不属于生产后台功能。

## Fixes and improvements

- **The first startup-observation failure is no longer masked by the next read**: the old startup observation had only 5 seconds, while AOSP `uiautomator` waits 1 second of quiet and up to 10 seconds globally for idle. On a busy target the App's own read watchdog expired first and closed the local connection; a later Observe then saw only `NOT_CONNECTED`, hiding the real first cause. Startup/continuation observation now shares one budget of at most 15 seconds (including the overlay-surface wait and real remaining time), and a fatal result is not retried blindly; the fixed `HIERARCHY_NOT_IDLE` / `READ_TIMEOUT` and `startFailureStage` keep the first typed cause. Ordinary calls keep their existing 15-second bound; the driver only reserves at most 500 ms of the original budget as a reporting margin, so an outer win can still be an ordinary `DEADLINE`.
- **Busy hierarchy and read timeout are refused with fixed reasons**: hierarchy output is `HIERARCHY_NOT_IDLE` only when the whole trimmed output is exactly the AOSP fixed idle sentence; a valid XML page containing the same words is not misclassified, and partial/invalid/unknown output stays fail-closed. `READ_TIMEOUT` covers both `open` and `read` of a read service: the transaction has abandoned the exact connection, the core publishes a logical disconnect/revoke in the same execute, keeps unknown, and fences the revoke to that connection owner so a newer connection survives; it does not claim the physical socket close completed. The existing hard watchdog still closes the stream and connection, with no stream-only keepalive.
- **Null startup window fields get only a bounded retry**: a complete official `mCurrentFocus=null` or `mFocusedApp=null` field line with its matching window missing is typed `NOT_READY` and mapped to `WINDOW_CHANGED`, retried only for explicit window transitions inside the existing shared startup budget. Missing fields, truncation, over-cap output, bad package/activity or unknown formats stay fail-closed; no partial window/target nodes are produced, and both-side window verification plus sensitive/overlay/target safety are not relaxed.
- **Cancel and unknown semantics are unchanged**: a post-grant cancel still rolls back exactly that epoch/task and propagates the original `Cancelled` without affecting a newer owner; `touched`/`afterWrite` results remain `UNKNOWN` and are never replayed. The existing scope and person-resume paths are unchanged.
- **The bounded-busy hook exists only in the independent test APK**: its default is 0, it adds no permission or service, and it is not a production background feature.

## Verification and limitations

- Four real flows passed with an independent package and the deterministic protocol fixture on the **API 35 / x86_64 emulator**:
