## 修复

- **关闭本机服务器上 OpenChamber 自带的更新入口**：OpenChamber 不再提示“有可用更新”，也不再显示“更新 OpenCode”按钮。这两个入口都会在原位执行 `npm i -g` 或 `opencode upgrade`，会破坏 PRoot 的链接结构，也会让应用记录的版本与实际不符。OpenChamber 和 OpenCode 请通过首页卡片更新。远程服务器不受影响。已有安装在下次启动服务器时生效，无需重装。
- 实现方式：应用在 Linux 系统中写入 OpenChamber 的策略文件 `/etc/openchamber/policy.json`，只固定 OpenCode 路径（不开启企业模式）；本机页面对 OpenChamber 更新检查的请求由应用直接回答“无更新”。

## Fixes

- **OpenChamber's own update entries are off for the on-device server**: OpenChamber no longer shows "update available" and no longer shows the "Update OpenCode" button. Both run `npm i -g` or `opencode upgrade` in place, which breaks the PRoot link layout and leaves the app's recorded versions out of date. Update OpenChamber and OpenCode from the Home card. Remote servers are not changed. Existing installs get this on the next server start, without a reinstall.
- How: the app writes OpenChamber's policy file `/etc/openchamber/policy.json` in the Linux system, pinning only the OpenCode path (enterprise mode stays off), and answers the local page's OpenChamber update check with "no update" itself.
