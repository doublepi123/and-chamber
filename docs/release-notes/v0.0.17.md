## 改进

- **输入后回车搜索**：修复工具声明支持 `submit`、原生层却返回 `UNSUPPORTED_PARAMETER` 的问题。`type(submit:true)` 现在对安全单行输入分发一次原生 Enter，确认受支持的当前标签页 GET 跳转、页面就绪和控制权后才报告成功，不需要代理自行拼接搜索结果网址。
- **代理自主选择页面模式**：agents 可按网站和任务选择手机或电脑页面，不必为布局选择再次询问。电脑页面默认固定为 **1920×1080 CSS 像素**，可在打开或调整页面时传入 `width`、`height` 自定义；宽度范围 640–3840，高度范围 360–2160，必须成对提供。
- **页面分辨率与窗口独立**：电脑视口在小窗、全屏、拖动、手机屏幕变化时保持不变，只缩放并居中显示。提交搜索、重新加载和同标签页导航保留选定尺寸；手机模式继续使用设备的可用浏览器区域。超宽内容不会偷偷放大桌面视口。
- **更稳定的默认控制**：首次页面回调早于挂载时保留并重新验证；临时布局或键盘门控不会提前结束打开等待。同一文档的并发授权探针复用控制 epoch，避免无实际撤销却误报需要授权。
- **失败不重复提交**：POST、重定向、密码/文件及受限制的凭据表单仍拒绝，不转写成 GET。超时、取消或未知结果不会伪报提交成功、自动再按 Enter，或由迟到回调恢复控制。

## Improved

- **Enter to search after typing**: fixes `submit` being advertised by the tool but refused with `UNSUPPORTED_PARAMETER` by the native layer. `type(submit:true)` now sends one native Enter to a safe single-line input and reports success only after a supported same-tab GET navigation, page readiness and control are confirmed. The agent need not construct a search-results URL as a workaround.
- **Agent-selected page layout**: agents can choose mobile or desktop for the site and task without asking the person merely to choose a layout. Desktop defaults to a fixed **1920×1080 CSS viewport**; `open` and `resize` accept paired `width` and `height` values, within 640–3840 and 360–2160 respectively.
- **Page resolution is independent of the window**: desktop layout remains fixed through small/full-screen presentation, dragging and phone screen changes; only its displayed scale and centering change. Submit, reload and same-tab navigation preserve the selected size. Mobile keeps the device's available browser area. Wide overflow content no longer expands the fixed desktop viewport.
- **More reliable default control**: early ready callbacks are retained and reverified after mounting, and temporary layout/keyboard gates no longer end an open's wait prematurely. Concurrent probes for one verified document reuse its control epoch instead of spuriously invalidating active reads.
- **No automatic duplicate submission**: POST, redirect, password/file and restricted credential-form submissions remain refused and are never rewritten as GET. Timeout, cancellation or an unknown outcome does not claim success, press Enter again, or allow a late callback to restore control.

## Verification and limitations

- 967 JVM and 292 Node tests pass; Android lint reports no errors. One optional upstream-source check is skipped because that source was not supplied.
- On an Android 15 / x86_64 emulator, 16 grant/site-data/native-submit/desktop-viewport regressions and 10 product cases pass, as do local plugin transport, restart and cold start.
- A real model clicked GitHub search, typed a query with `submit:true`, reached repository results and read the first three entries correctly without opening a constructed search URL.
- Checked default 1920×1080, custom 1366×768, resize to 1280×720, wide overflow and dynamic viewport meta. WebView density conversion can introduce about two CSS pixels of rounding; actual measurements are reported without spoofing DPR or `screen`. Capture remains the displayed page region, not an upscaled preview presented as a full-resolution screenshot.
- Desktop minimum scale prevents expansion below the configured baseline while still allowing zoom-in. Not verified on physical arm64 devices; existing complex-login, POST and redirect restrictions remain.
