## 修复

- **共享存储上的 git 仓库**：修复在 `~/projects`（`/sdcard/AndChamber/projects`）里克隆仓库失败的问题（`unable to write/rename temporary '*.pack' file`）。AndChamber 每次启动服务时会为 `~/projects` 下的仓库自动配置 git：
  - `core.createObject=rename`：共享存储不支持硬链接，改用重命名写入对象。
  - `core.fileMode=false`、`core.symlinks=false`：共享存储不保留可执行权限和符号链接，避免所有文件都显示为已修改。
  - `safe.directory=/root/projects/*`：共享存储上的文件属于 Android 媒体用户，避免 git 报“所有者可疑”。
  - 配置写在私有目录的 `~/.gitconfig` 中带标记的一段，不影响你自己的 git 配置，也不影响 `~/projects-private` 里的仓库。

## 提示

- 共享存储写入大量小文件较慢，大仓库（数千个文件）克隆到 `~/projects` 可能需要几分钟。大项目或需要 `node_modules`、可执行脚本的项目建议放在 `~/projects-private`。
- 共享存储上的脚本没有可执行权限，请用 `sh script.sh` 运行。

## Fixes

- Git repositories under `~/projects` (shared storage) now work: cloning no longer fails with `unable to write/rename temporary '*.pack' file`. AndChamber configures git for repos under `~/projects` on every start (`core.createObject=rename`, `core.fileMode=false`, `core.symlinks=false`, `safe.directory=/root/projects/*`) via a managed block in the private `~/.gitconfig`; your own git settings and `~/projects-private` are untouched.

## Notes

- Shared storage is slow with many small files; cloning a large repository into `~/projects` can take several minutes. Use `~/projects-private` for large projects or ones that need `node_modules` or executable scripts.
