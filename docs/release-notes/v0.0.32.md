# v0.0.32 — 读屏不再误报“设备不可用”

> Reading the screen no longer reports "unavailable on this device" by mistake.

## 修复

- **读屏偶发空结果会自动重读**：在一台真实的 Android 17 手机上，如果上一次读屏还没在手机上结束，下一次读屏会什么都读不到（系统提示 UiAutomation 已被占用）。以前这会被当成驱动故障，报 `DRIVER_UNAVAILABLE`。现在会在同一次调用的时间限制内，每隔一小段时间重新读，最多 6 次；只读，不点击、不输入。
- **一直读不到时，报“页面暂时读不到”**：重读后仍为空，返回 `HIERARCHY_NOT_IDLE`。按已有规则，这会保留原任务和授权，不会被当成需要人工处理。
- **`DRIVER_UNAVAILABLE` 的提示更准确**：不再说“此设备不可用”，而是说明这次读取的内容无法解析，不代表设备不支持或断线，也不能证明之前的操作是否已经生效；不要重复执行改动类操作，先重新读屏。

## 验证范围

- 在一台真实的 Android 17 / arm64 手机上做了只读采样：前台应用的页面结构能正常读取；两次读屏重叠、或刚放弃一次读屏后马上再读，都能稳定复现空输出，等上一次结束后再读就恢复正常。模拟器上也能复现同样的重叠现象。
- 2,074 项 JVM 测试、361 项 Node 测试（360 项通过，1 项为原有的跳过）、72 项 Python 测试全部通过，lint 和 debug/AndroidTest 打包也通过。
- 尚未在真机上安装新版本完整复测；上一次读屏为什么会被放弃，没有在真机上单独验证。

## Fixes

- **An empty screen read is re-read**: on a real Android 17 phone, a hierarchy read that overlaps an earlier on-device read still running returns nothing (UiAutomation is already registered). It used to be reported as `DRIVER_UNAVAILABLE`. The read is now retried a bounded number of times (at most six) within the same call deadline. It only reads; it never taps or types.
- **A read that stays empty is `HIERARCHY_NOT_IDLE`**: under the existing rules this keeps the original task and grant and is not a reason for a person handoff.
- **Accurate `DRIVER_UNAVAILABLE` message**: it no longer says the device is unsupported. It says this call's output could not be parsed, which proves neither an unsupported device nor a lost connection, and does not confirm whether an earlier action applied. Do not repeat a mutating action; take a fresh snapshot.

## Verification scope

- Read-only sampling on a real Android 17 / arm64 phone: the foreground app's hierarchy reads normally; overlapping reads, or a read right after an abandoned one, reproducibly return empty output, and reads recover once the earlier one finishes. The same overlap reproduces on the emulator.
- 2,074 JVM, 361 Node (360 passed plus one existing skip) and 72 Python tests passed, with Android lint and debug/AndroidTest packaging.
- The new build has not yet been installed for a full re-test on the phone, and why the earlier read was abandoned was not separately verified on the device.
