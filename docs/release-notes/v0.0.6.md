## 新功能

- **启动时回到上次使用的 OpenChamber**：App 会记住上次打开的实例（本机或远程服务器）以及所在页面/会话，下次启动直接回到那里。可在设置中关闭「启动时打开上次使用的 OpenChamber」。如果上次是主动回到首页的，启动时仍按原来的「自动打开本机实例」设置处理。

## 修复

- **Cloudflare Access 认证后又出现 OpenChamber 密码页**：Access 登录完成回到服务器时，旧页面发出的未登录会话检查可能在 App 用已保存密码登录之后才返回 401，把刚写入的登录 Cookie 删掉，于是又显示解锁页。现在 App 会先让旧页面停下，再读取 Cookie 并登录，然后才加载服务器页面。认证交接失败时，「重试」会重新开始一次完整的交接；新页面的网络错误也能正确显示。
- 在 Access 认证完成之前，恢复页面会一直保留，不会提前跳走。

## 其他

- 内置运行环境中的 PRoot 改为从固定版本的源码编译。
- 新增真实 WebView 的回归测试（仅用于调试构建，不会打进发布版 APK）。

## New

- **Reopen the last used OpenChamber on launch**: AndChamber remembers the last instance you opened (local or remote) and the page or session you were on, and returns there on the next launch. Turn it off with "Open last used OpenChamber when the app starts". If you went back to Home last time, launch follows the existing "open the local instance automatically" setting.

## Fixes

- **OpenChamber's password page shown again after Cloudflare Access login**: when Access returned to the server, a session check from the old page could get its 401 after AndChamber had already logged in with the saved password, and that response deleted the new login cookie. AndChamber now stops the old page first, then reads cookies and logs in, and only then loads the server page. If the handoff fails, Retry starts a fresh handoff, and network errors on the new page are shown correctly.
- The resume page now stays until Access authentication has finished.

## Other

- PRoot in the bundled runtime is now compiled from pinned sources.
- Real-WebView regression tests (debug builds only; not shipped in the release APK).
