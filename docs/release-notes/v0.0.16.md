## 改进

- **代理优先的浏览器**：前台打开的网页在就绪并通过页面、会话和连接检查后，默认允许代理操作，不再每次等待点击 Allow。代理需要使用已隐藏的页面时，会在前台重新弹出小窗；不会把 App 从后台强行拉起。
- **全屏、小窗和隐藏**：支持全屏与小窗切换、隐藏后恢复，以及更大的拖动和缩放触控区域。页面使用固定的手机尺寸视口，调整窗口只缩放显示，不反复重排网页；滑动页面、拖动窗口、缩放和全屏切换不暂停代理。
- **地址栏与手机适配**：显示当前网址，支持编辑地址和重新加载。键盘出现或屏幕空间不足时使用紧凑布局，修复窄屏、大字体下网址输入框和打开按钮被键盘遮挡的问题。
- **明确的接管操作**：点“接管”后，代理不能靠再次打开页面或普通操作抢回控制；可用“恢复代理”主动交还控制。隐藏只收起窗口，若想阻止后续自动操作，请使用“接管”。
- **更可靠的授权和截图**：修复聊天页重复完成回调撤销浏览器授权、页面重新挂载时授权丢失，以及接管后无法恢复代理的问题。截图核对缩放后的网页范围并等待硬件绘制帧提交；网址输入遮罩不会被当作网页截图返回。

- 在 Android 15 / x86_64 模拟器上验证了 7 项授权与站点数据回归、10 项产品用例、8 项生命周期及取消安全用例、17 项浏览器 smoke 检查，以及本地插件传输、重启和冷启动。
- 真实模型自行打开网页并读回标题，全程无需点击 Allow。另实测了 320dp 窄屏、1.3 倍字体和键盘下的小窗、全屏及网址输入。

## Improved

- **Agent-first browsing**: a foreground open defaults to agent control once the exact page is ready and its page, session and connection checks pass. There is no per-open Allow tap. When an agent needs a hidden page, its small window can reappear while the app is in front; it never brings the app forward from the background.
- **Full screen, small window and hide**: switch presentations, hide and restore the page, and use larger drag and resize touch targets. The page keeps a fixed phone-sized viewport; resizing scales its presentation instead of repeatedly reflowing the website. Scrolling, dragging, resizing and full-screen switching do not pause the agent.
- **Address bar and phone layouts**: see the current address, edit it and reload. Compact layouts accommodate the keyboard and limited screen space, including the fix for address fields and Open buttons covered by the keyboard on narrow screens with large fonts.
- **Explicit takeover**: after Take over, the agent cannot reclaim control by opening another page or sending an ordinary action. Use Resume agent to hand it back. Hiding only puts the window away; use Take over to prevent later automatic actions.
- **More reliable grants and capture**: fixes duplicate chat-page completion callbacks revoking browser control, lost grants while a page remounts, and Resume agent failing after takeover. Capture checks the transformed page rectangle and waits for a committed hardware frame; an address-entry overlay is not returned as a page screenshot.

## Verification and limitations

- 930 JVM, 288 Node and 72 Python tests pass; Android lint reports no errors. One optional upstream-source check is skipped because that source was not supplied.
- Checked on an Android 15 / x86_64 emulator: 7 grant/site-data regressions, 10 product cases, 8 lifecycle/cancellation-safety cases, 17 browser smoke checks, local plugin transport, restart and cold start.
- A real model opened a page and returned its title without an Allow tap. A 320dp screen with font scale 1.3, the keyboard, small-window/full-screen presentation and address entry were also checked.
- **Capture compatibility change**: capture now requires Android 10 (API 29) or later and hardware frame-commit confirmation. Capture fails closed on Android 8–9 instead of using a software fallback that might return the wrong pixels.
- Not verified on physical arm64 devices. The browser remains experimental; the existing controlled-navigation, POST, redirect and complex sign-in limits are documented in `docs/embedded-browser-control.md`.
