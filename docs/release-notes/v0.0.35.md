# v0.0.35 — 浮窗不再把代理“误停”

> The progress capsule no longer stops the agent by mistake.

## 修复

- **浮窗内容一更新，代理就被停下**：以前浮窗只要有一点变化，比如聊天里来了一条新提醒、浮窗被展开或收起、被拖动了位置，代理的下一次操作就会被当成“浮窗可见性无法确认”。结果是代理被停下，还被标成“结果未知”。这正是“浮窗可见性无法确认 / 操作已发出，但没能确认是否生效”的主要来源。现在这类显示上的变化不再中断任务：每次操作前都会重新读取浮窗的真实位置，再做判断。
- **点到浮窗上只拒绝这一下**：如果代理要点的位置、滑动的路线或要输入的框正好被浮窗挡住，现在只拒绝这一个操作，并返回新的 `OVERLAY_OBSTRUCTED`，告诉代理换个位置或先滚动页面。任务不会被停下，也不会被标成结果未知。
- **真正的风险仍然会停下**：浮窗被隐藏或无法确认是否可见、换成了另一个浮窗、屏幕方向或尺寸变化，仍按原来的规则停下。截图时仍会先隐藏浮窗。

## 验证范围

- 在 API 35 / x86_64 模拟器上，用真实的系统浮窗跑了浮窗安全测试：截图里不会出现浮窗；点在浮窗上被单独拒绝，点在浮窗外正常执行；浮窗被移动、放大后，按它新的真实位置判断；目标 App 要求隐藏浮窗时仍然拒绝操作。读屏、点击、返回、输入的端到端检查也全部通过。
- 2,080 项 JVM 测试、361 项 Node 测试（360 项通过，1 项为原有的跳过）通过，lint 和 debug/AndroidTest 打包通过。
- 还没在真机上复测。

## Fixes

- **Capsule updates no longer stop the agent**: any display change (a chat notice, expand/collapse, a drag) bumped the capsule revision, and the next action treated it as "overlay visibility could not be confirmed", stopping the agent with an unknown outcome. The revision is no longer part of the observation identity; each action re-reads the real capsule frame and checks against it.
- **Hitting the capsule refuses only that action**: a point, swipe or input focus on the visible capsule now returns `OVERLAY_OBSTRUCTED` without stopping control or marking anything unknown.
- **Real risks still stop**: a hidden or unverifiable overlay, a new display owner/generation, or a rotation/display change still fail closed. Capture still hides the capsule.

## Verification scope

- Real-overlay safety instrumentation on an API 35 / x86_64 emulator: capture self-exclusion, inside-capsule refusal with outside taps sent, a moved/expanded capsule checked against its fresh frame, and target-requested overlay hiding still refused; the real-driver observe/tap/back/input checks also passed.
- 2,080 JVM and 361 Node tests (360 passed plus one existing skip) passed, with lint and debug/AndroidTest packaging.
- Not yet re-tested on a real phone.
