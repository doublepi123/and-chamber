## 修复

- **运行时安装**：输出管道关闭时的异常不再逃逸到应用进程；安装命令的收尾时间窗口改为在命令结束后计算，避免长命令被过早的收尾时限误判为失败。
- **异常恢复**：自动恢复预算耗尽时，先尝试停止服务器并清理归属进程，再进入最终失败状态，修复前台服务结束后遗留服务器的路径。
- **网络切换**：服务运行期间，运行时会跟随系统网络的 DNS 变化，更新容器内的 `/etc/resolv.conf`。
- **通知回复与权限操作**：
  - 发请求前复核运行时启动身份；身份变化时停止请求并清除旧会话。
  - 阻止 OkHttp 因 HTTP 503 + `Retry-After: 0` 隐式重放通知操作，避免这类重复提交。
  - 失败或结果不确定时，保留原通知的操作、草稿和会话入口，不会自动重发。
  - 查询待处理项失败时保留原状态，不会误取消。
  - 已发送提示的计时器只清除它自己创建的那一条，不会删除同一通知 ID 的新事件或恢复后的草稿。
  - 回到首页或切换远程服务器时，不再因错误的前台判断抑制本地通知，并遵循“总是通知”设置。
- **WebView 登录隔离**：每个服务器（同一主机的不同端口也一样）使用独立的 WebView Profile，认证 Cookie 只写入对应的 Profile。
- **HTTP 下载**：应用内的 HTTP 下载只在同源时携带登录 Cookie；跨源跳转后，整条下载链路都不再携带凭据。拒绝从 HTTPS 降级到 HTTP，也不接受非法的重定向地址。
- **镜像检查**：修复镜像检查工具，并加入离线 Python 测试（`scripts/tests`）。

## 兼容性与行为变化

- **内嵌页面需要 WebView 多 Profile 支持**：本机和远程服务器的内嵌页面都需要系统 WebView 支持 `MULTI_PROFILE`。不支持或绑定失败时，页面不会加载，并提示更新 WebView 提供程序（Android System WebView 或 Chrome）。本机后台服务、首页和通知仍然可用。
- **远程服务器可在外部浏览器打开**：在不能内嵌时，可以使用“在浏览器中打开”打开格式有效的已保存地址，不会附加密码、Cookie 或令牌。
- **升级后可能需要重新登录**：新 Profile 首次打开时可能要求登录。已有的服务器配置、密码和旧网页数据会保留，不会被清理或迁移。
- **原生下载跟随应用进程**：下载在应用运行时进行，进程被杀后不会断点续传或自动恢复。
- **跨源导航交给外部浏览器**：作为顶层导航处理的跨源链接仍在浏览器打开；已进入应用下载器的重定向按上述凭据规则处理。
- 本版本为 `0.0.4`（versionCode 4）；OpenChamber 2.4.0、OpenCode 2.0.32、支持的 ABI、最低系统版本和签名方式未改变。

## Fixes

- **Runtime installation**: output-pipe closure errors no longer escape into the app process. The output teardown window starts after the command returns, preventing long commands from being mistaken for failures because of an expired cleanup deadline.
- **Crash recovery**: when the automatic recovery budget is exhausted, stopping the server and cleaning up owned processes is attempted before entering the final failure state, fixing the path that left a server behind after the foreground service ended.
- **Network changes**: while the server runs, the runtime follows DNS changes on the system network and updates `/etc/resolv.conf` inside the container.
- **Notification replies and permission actions**:
  - Requests recheck the current runtime launch; a changed identity stops the request and clears the old session.
  - Notification operations cannot be implicitly replayed by OkHttp after HTTP 503 with `Retry-After: 0`, preventing duplicates from that follow-up mechanism.
  - On failure or an uncertain result, the original notification actions, draft and session entry are kept, and nothing is resent automatically.
  - If checking pending items fails, the existing state is kept rather than cancelled.
  - The "Sent" timer removes only the notification it created. It no longer removes a newer event with the same notification ID, or a restored draft.
  - Home and remote pages no longer suppress local notifications merely because the app is foreground, and the "always notify" setting is respected.
- **WebView sign-in isolation**: each server, including servers on the same host with different ports, uses its own WebView profile, and authentication cookies are written only to that profile.
- **HTTP downloads**: in-app HTTP downloads send the sign-in cookie only to the same origin. After a cross-origin redirect, the rest of the chain carries no credentials. Downgrades from HTTPS to HTTP are refused, and invalid redirect locations are rejected.
- **Mirror checker**: the mirror checking tool is fixed, and offline Python tests (`scripts/tests`) are added.

## Compatibility and behavior changes

- **Embedded pages need WebView multi-profile support**: embedded pages for both the local server and remote servers require `MULTI_PROFILE` in the system WebView. If it is missing or binding fails, the page does not load and asks you to update the WebView provider (Android System WebView or Chrome). The local background service, Home and notifications keep working.
- **Remote servers can open in an external browser**: when embedding is not possible, "Open in browser" opens the saved address after URL validation, without adding passwords, cookies or tokens.
- **You may need to sign in again after upgrading**: a new profile may ask you to sign in on first open. Existing server settings, passwords and old web data are kept; nothing is cleared or migrated.
- **Native downloads follow the app process**: downloads run while the app is running. If the process is killed, there is no resume or automatic recovery.
- **Cross-origin navigation opens externally**: links handled as cross-origin top-level navigation still open in the browser; redirects already handled by the native downloader follow the credential rules above.
- The app version is `0.0.4` (versionCode 4). OpenChamber 2.4.0, OpenCode 2.0.32, the supported ABIs, the minimum Android version and the signing setup are unchanged.
