## 新功能

- **聊天页内的浏览器小窗（实验性）**：代理通过 AndChamber 注入的 OpenCode 工具 `andchamber_web` 打开网页，页面显示在聊天页上方的原生小窗里。小窗可拖动、放大和还原，放大还原不重新加载，滚动位置和输入内容都保留；会自动避开输入框和键盘。
- **需要你允许才能控制**：代理打开网页不等于获得控制权，你在小窗里点“允许代理”后，代理才能读取页面、点击、输入、滚动和截图。切换会话、退到后台、关闭小窗或重启服务器都会收回控制权，之后需要重新允许。随时可以点“接管”自己操作。
- **电脑版与鼠标**：小窗可切换为电脑版布局（桌面 UA，1024 CSS 宽度），也可切换为鼠标模式，网页会收到真实的移动、点击、拖动和滚轮事件。
- **打开网页**：聊天页右侧边缘的菜单新增“打开网页”，输入网址后在当前会话的小窗中打开（仅公网 https）。
- **清除网站数据**：小窗的“更多”菜单新增“清除网站数据”，会退出小窗里登录的网站，影响本机所有会话；不影响 OpenChamber 页面本身的登录。

## 变更

- 首页原来的独立 Browser 和 `andchamber_browser` MCP 工具已移除，由上面的小窗取代。升级时 App 只删除它自己的旧文件，不改动你的 `opencode.json`、共享文件夹或网站登录数据。
- OpenChamber 保持官方 npm 包，App 内的 OpenChamber/OpenCode 更新照常可用。OpenCode 配置只追加插件目录，不写入权限、MCP 或工具设置。
- OpenChamber 自带的网页工具：仅当你没有设置过时，App 才将其关闭（`agentWebToolEnabled: false`）；你在 OpenChamber 设置里重新打开后，App 不会改回，此时代理会同时看到两个浏览器工具。
- 修复：App 启动时可能重复启动本机服务器，导致 OpenChamber 刚启动就被重启。

## 已知限制

- 工具令牌在 guest 内可读：代理执行的命令若读到它，可以直接驱动你已经允许的页面；没有允许过的页面仍无法驱动。令牌每次启动更换，只监听 127.0.0.1，服务停止即失效。
- OpenChamber 聊天抽屉里没有这个浏览器的入口；平板（桌面布局）上 OpenChamber 自带的 iframe 浏览器面板无法隐藏。
- 开启无障碍服务时，鼠标模式下没有悬停效果。
- 会话从页面网址 `?session=` 读取；网址不变的页内切换无法识别。
- 详见 `docs/embedded-browser-control.md`。

## New

- **Floating browser window in the chat (experimental)**: the agent opens web pages through `andchamber_web`, an OpenCode tool injected by AndChamber, and they show in a native window above the chat. You can drag, enlarge and restore it; enlarging and restoring never reloads the page, and the scroll position and typed text are kept. The window stays clear of the composer and keyboard.
- **You allow control**: opening a page does not give the agent control. The agent can read, click, type, scroll and capture only after you tap **Allow agent** in the window. Switching chats, going to the background, closing the window or restarting the server takes control away; you allow it again afterwards. Tap **Take over** at any time to use the page yourself.
- **Computer layout and mouse**: switch the window to a computer layout (desktop user agent, 1024 CSS px wide) or to mouse mode, where pages receive real move, click, drag and wheel events.
- **Open web page**: the menu on the chat's right edge has **Open web page**, which opens an address in this chat's window (public https only).
- **Clear site data**: the window's **More** menu can clear site data. It signs you out of websites opened in the window, for all chats on this phone; the OpenChamber page's own sign-in is not affected.

## Changes

- The separate Browser on Home and the `andchamber_browser` MCP tool are removed; the floating window replaces them. On upgrade the app deletes only its own old files. It does not touch your `opencode.json`, the shared folder or website sign-ins.
- OpenChamber stays the official npm package, and in-app OpenChamber/OpenCode updates keep working. The OpenCode config only gains the plugin directory; no permission, MCP or tool settings are written.
- OpenChamber's own web tool: the app turns it off (`agentWebToolEnabled: false`) only if you have never set it. If you turn it back on in OpenChamber's settings, the app leaves it on, and the agent then sees both browser tools.
- Fixed: on launch the app could start the on-device server twice, restarting OpenChamber right after it came up.

## Known limitations

- The tool token is readable inside the guest. A command run by the agent that reads it can drive a page you have already allowed; pages you have not allowed stay out of reach. The token changes on every start, listens on 127.0.0.1 only, and stops working when the server stops.
- OpenChamber's chat drawer has no entry for this browser, and on tablets (desktop layout) OpenChamber's own iframe browser panel cannot be hidden.
- With an accessibility service on, mouse mode has no hover.
- The chat is read from the page address (`?session=`); an in-page switch that keeps the address is not noticed.
- See `docs/embedded-browser-control.md`.
