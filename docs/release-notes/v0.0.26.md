## 新增与改进

- **本机手机操控（实验，默认关闭）**：Android 11+ 可通过原生页面确认一个目标应用、任务、允许动作和短时授权，使用本机 `andchamber_phone` 工具观察、点击、滑动、输入和返回。连接不等于授权，重连不会恢复旧操作。
- **同机无线调试配对**：在系统配对弹窗保持打开时，通过通知依次填写配对端口和验证码；配对记录可在应用重启后继续使用。配对码不进聊天、不由应用持久保存。
- **跨 App 进展浮窗（可选，默认关闭）**：单独授权并测试可见、可点后，用可拖动吸边胶囊跟进任务。展开面板区分原生事实、已发出操作和未核验的代理说明，支持键盘避让、横竖屏位置记忆及大字体。
- **人工交接与安全停手**：浮窗接管会撤销观察和操作权限；普通暂停只停止新操作。`need_user` 先撤权再交给用户，继续须原生重新确认；`finish` 和用户结束任务保留待核对结果，不声称业务成功。
- **异常不重放**：在途结果未知、断线、熄屏、权限失效或进程重启后，不自动恢复控制或重复操作。浮窗被目标隐藏或不可用时失败关闭，通知仍是独立恢复入口。
- **窗口隔离**：使用真实窗口矩形和代际复核，阻止代理操作自己的浮窗；观察和截图期间受控隐藏自家浮窗，恢复等待首帧。既有浏览器授权规则保持不变。

## 验证与重要边界

- 1,741 项 JVM、335 项 Node、72 项 Python 测试通过；另有 1 项原有 Node 夹具跳过。20 项原生接线/界面检查通过，Android lint 与 APK 构建通过（保留 lint warnings/information）。
- API 35 / x86_64 模拟器完成真实 OpenCode → 插件 → 原生 TLS ADB → 虚构目标应用的输入、保存、切页、返回、滚动、截图和交接流程；还覆盖浮窗权限、隐藏、接管、通知失效、键盘、旋转与冷启动恢复。详见 `docs/testing-phone-control.md` 和 `docs/testing-phone-overlay.md`。
- **模型端使用本地协议夹具，不代表真实模型推理或自主规划/续跑能力。** arm64 真机、厂商系统、TalkBack 实际语音及多窗口差异尚待补验；不能把模拟器结果推广到所有设备。
- **仅适用于可信的整个本机 runtime。** 同 UID 的插件/子进程不构成强隔离；ADB 配对是设备级授权，目标应用检查不是 OS 沙箱。授权观察可能发送给当前模型服务商。
- 当前输入仅支持声明的 **ASCII 子集**，不支持中文/Unicode、密码输入或自动提交；不能保证识别所有登录或敏感页面。输入敏感内容前请接管或返回 AndChamber。

## Features and improvements

- **Local phone control (experimental, off by default):** Android 11+ can natively approve one target app, task, action set and short lease for `andchamber_phone`. Observe, tap, swipe, type and Back are bounded operations. Connecting or reconnecting never grants control or replays an old operation.
- **Same-device wireless pairing:** enter the pairing port and code through notification replies while Android's pairing dialog stays open. The native identity and non-secret receipt survive app restarts; codes are not sent through chat or persisted by the app.
- **Optional cross-app progress overlay, off by default:** separately allow and test a draggable edge-snapped capsule. Its panel distinguishes native facts, delivery receipts and unverified agent notes, with IME avoidance, per-direction positioning and large-text support.
- **Human handoff and stop controls:** takeover revokes both observation and changes; plain Pause stops new mutations only. `need_user` revokes before handing over, and continuing requires native confirmation. Model `finish` and user End retain results needing review, not verified business success.
- **No uncertain replay:** disconnects, screen-off, permission loss, process restart and unknown outcomes do not automatically restore control. Hidden/unavailable overlays fail closed; notifications remain an independent recovery path.
- **Window isolation:** actual window frames and generation checks exclude the app's own controls. Protected collection hides the overlay and waits for its restoration frame. Embedded-browser authorization is unchanged.

## Verification and limitations

- 1,741 JVM, 335 Node and 72 Python tests pass; one existing Node fixture is skipped. Twenty native wiring/UI checks, Android lint and APK packaging pass; lint retains warnings/information.
- Real OpenCode/plugin/native TLS ADB loops run on an API 35/x86_64 emulator against synthetic content. See `docs/testing-phone-control.md` and `docs/testing-phone-overlay.md` for the action, handoff, permission, capture, IME, rotation and recovery matrix.
- **The model endpoint is a deterministic protocol fixture, not actual reasoning or autonomous continuation.** Physical arm64/OEM, spoken TalkBack and multi-window behavior remain unverified.
- **Trust the entire local runtime.** Same-UID plugins/subprocesses are not strongly isolated, ADB pairing has device-level authority, and target checks are not an OS sandbox. Authorized observations can reach the configured model provider.
- Only the declared **ASCII subset** is supported for input: no Unicode/password entry or automatic submission, and no promise to detect every sensitive page. Take over or return to AndChamber before handling sensitive content.
