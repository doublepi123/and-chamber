# v0.0.40 — 已登录的第三方授权由代理直接点

> The agent taps an already signed-in third-party authorization itself.

## 改进

- **已登录的第三方授权，代理自己点“同意”**：例如 QQ 或微信弹出“允许该应用使用你的头像和昵称”，账号已经选好、只需要点“同意/允许”时，只要这是你交代的任务里的一步，代理会直接点同意，然后继续做，不再停下来请你处理。代理不会切换账号、创建账号或改动已选的账号。
- **仍然交给你处理的情况**：需要输入密码，或者需要选择用哪个账号登录；输入验证码；支付或其他涉及钱的确认；系统权限弹窗。这些情况代理仍会停下，等你在手机上自己完成。
- 这是给代理的使用规则，不是 App 强制执行的限制。

## 验证范围

- 工具说明的文案测试已更新并通过：361 项 Node 测试（360 项通过、1 项原有跳过），相关 JVM 测试通过，打包通过。
- 代理是否真的按这条规则操作，取决于所用模型，没有在设备上验证。

## Improvements

- **Signed-in third-party authorizations**: when an authorization page (for example QQ/WeChat "allow this app to use your avatar and nickname") already has the account selected and is part of the requested task, the agent taps Agree/Allow itself and continues. It never switches, creates or changes the selected account.
- **Still handed to you**: entering a password or choosing which account to sign in with, verification codes, payments and system permission dialogs.
- This is tool guidance, not an enforced native rule.

## Verification scope

- Tool-description tests updated and passing (361 Node tests, 360 passed plus one existing skip), relevant JVM tests and packaging passed.
- Real-model compliance with the guidance was not verified on a device.
