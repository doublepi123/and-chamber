## 新增与改进

- **配置一次，直接在聊天里控制手机**：原生保存允许的应用、动作和有效期限后，本机 OpenChamber 聊天中的 `request` 可在范围内直接创建任务，不再逐任务跳回原生授权页。首次请求绑定当前 runtime 和会话；每个任务仍有独立 epoch 和短租约。
- **工具就绪可验证**：插件确认 `andchamber_phone` 已进入工具注册表后提供只读 RPC，App 在当前 launch 内限时检查通过才显示 Ready。已有 runtime 需要先开启配置时，由用户明确确认一次重启。
- **允许应用与前台证据**：`apps` 只返回预授权应用，`open_app` 只能打开当前任务的同一目标，并实际观察确认前台。普通预装应用可按范围选择；宿主控制页、系统授权/安装/锁屏及密码输入仍禁止代理操作。
- **人工处理后在原会话继续**：需要用户、接管、未知结果、锁屏、断线或 runtime 变化仍会停手。原生确认后创建新 epoch、重新观察目标，并向原会话只发一次继续提示；不自动重放旧操作，也不把恢复当成业务成功。
- **跨 App 浮窗更可靠**：首次读屏前等待当前任务的浮窗完成 attach，正常截图隐藏/恢复与真实失效分开处理。失效时停止新动作并保留原因和恢复入口，不再把可见性故障冒充用户接管或让胶囊静默消失。普通打开聊天不撤权，进入真正的手机控制页才撤权。
- **启动与恢复修正**：修复前台服务通知准备顺序、任务回滚的新旧所有权、授权倒计时刷新，以及恢复提示发送失败时的界面状态。

## 验证与重要边界

- 1,817 项 JVM、349 项 Node（348 通过＋1 项原有跳过）、72 项 Python 测试通过；20 项设备原生接线/界面检查通过，Android lint 与 APK 构建通过（保留 lint warnings/information）。
- API 35 / x86_64 模拟器完成“旧 runtime → 开启配置 → 确认重启 → RPC Ready → 聊天直接启动 → 浮窗人工等待 → 原会话继续”的真实链路。独立目标确认输入内容，打开聊天不撤权，`open_app` 返回后确认目标在前台，原生继续提示只出现一次。详见 `docs/testing-phone-control.md`。
- **模型端使用确定性本地协议夹具，不代表真实模型推理或自主规划能力。** arm64 真机、厂商系统、TalkBack 和多窗口差异未验证。主动撤销浮窗权限时的运行中撤权未纳入本轮通过项；当时租约已结束。
- **仅适用于可信的整个本机 runtime。** 同 UID 插件/子进程不构成强隔离；ADB 配对具有设备级权限，目标应用检查不是 OS 沙箱。授权观察可能发送给当前模型服务商。
- 当前输入仅支持声明的 **ASCII 子集**，不支持中文/Unicode、密码输入或自动提交；不能保证识别所有登录或敏感页面。输入敏感内容前请接管或返回 AndChamber。

## Features and improvements

- **Configure once, then use chat directly:** the native standing scope binds the current runtime/session on the first valid request. In-scope `request` starts without per-task native confirmation; every task still receives a fresh epoch and a short lease.
- **Verifiable tool readiness:** the plugin exposes a read-only RPC only after confirming tool registration. The App checks that exact launch before showing Ready; an existing runtime is restarted only after explicit user confirmation.
- **Bounded apps and foreground proof:** `apps` exposes only preauthorized apps. `open_app` allows only the current task's same target and verifies its foreground observation. Host, system authorization, installer, lock-screen and password surfaces remain forbidden.
- **Native continuation in the original session:** stops still require a person. Native continuation creates a fresh epoch, re-observes the target and sends exactly one fixed wake-up prompt to the original session, without replaying old actions or claiming business success.
- **More reliable cross-app overlay:** first reads wait for the current epoch's surface. Normal capture hide/restore is separated from real visibility failures, which stop new actions, preserve reasons and offer recovery instead of pretending a takeover or silently removing the capsule. Ordinary chat does not revoke; the real native phone page does.
- **Startup and recovery fixes:** correct foreground-service preparation order, exact-owner rollback, standing countdown refresh and continuation-failure presentation.

## Verification and limitations

- 1,817 JVM, 349 Node (348 passed plus one existing skip), and 72 Python tests pass. Twenty native wiring/UI checks, Android lint and APK packaging pass; lint retains warnings/information.
- API 35/x86_64 emulator acceptance covers the old-runtime → configuration → confirmed restart → RPC Ready → direct chat start → overlay handoff → original-session continuation flow. Independent target effects and one native continuation prompt are checked. See `docs/testing-phone-control.md`.
- **The model is a deterministic protocol fixture, not real reasoning.** Physical arm64/OEM, TalkBack and multi-window behavior remain unverified. Active-lease overlay-permission revocation is not claimed: the lease had already expired before that check.
- **Trust the entire local runtime.** Same-UID plugins/subprocesses are not strongly isolated, ADB pairing has device-level authority, and target checks are not an OS sandbox. Authorized observations can reach the configured model provider.
- Only the declared **ASCII subset** is supported for input: no Unicode/password entry or automatic submission, and no promise to detect every sensitive page. Take over or return to AndChamber before handling sensitive content.
