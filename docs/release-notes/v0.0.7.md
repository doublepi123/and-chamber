## 新功能

- **实验性独立浏览器控制**：Home 新增独立 Browser，使用自己的 WebView profile，不复制主 OpenChamber 页面的 Cookie。默认关闭。用户先在聊天里发起任务，再在前台打开 Browser 并授权；离开、暂停、触摸接管、到期、runtime 停止或更换都会撤权。再次使用必须重新授权。
- 本机 OpenCode 通过 stdio MCP `andchamber_browser` 使用六个工具：`browser_navigate`、`browser_snapshot`、`browser_click`、`browser_type`、`browser_scroll`、`browser_capture`。凭证是动态生成的私有 token，不写入共享配置。页面只允许公网 `https`。旧 snapshot ref 在新文档中失效。
- 这不是现有 OpenChamber browser tool 的自动连接，也不是完整出站防火墙。复杂 POST、登录流、iframe DOM、CAPTCHA、文件上传和任意脚本都不支持。

## New

- **Experimental independent browser control**: Home has a separate Browser with its own WebView profile. It does not copy cookies from the main OpenChamber page. Control is off by default. Send the task in chat first, then open Browser in the foreground and grant control. Leaving, pausing, taking over by touch, expiry, runtime stop, and runtime replacement all revoke it. A new grant is required afterwards.
- Local OpenCode reaches six tools through the stdio MCP server `andchamber_browser`: `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_scroll`, and `browser_capture`. The credential is a dynamically generated private token and is not written to shared config. Pages are public `https` only. Old snapshot refs do not survive a fresh document.
- This does not connect an existing OpenChamber browser tool, and it is not a complete outbound firewall. Complex POST, login flows, iframe DOM, CAPTCHA, file upload, and arbitrary script are unsupported.

## Other

- This is a 0.x pre-release, not an F-Droid build. PRoot is compiled from pinned sources; that does not make the whole distribution reproducible.
- The v0.0.6-based release candidate passed 471 JVM, 46 Python, and 24 Node checks. The 17 emulator smoke checks and 26 host Node to emulator RPC/WebView end-to-end checks also passed again after integration.
- The on-device arm64 OpenCode → MCP → WebView loop is not verified. No prompt was sent to a real model. A physical device remains optional.
