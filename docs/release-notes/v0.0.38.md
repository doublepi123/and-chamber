# v0.0.38 — 浮窗不再闪、打开即用、授权所有 App

> Steady capsule, open-and-use launch, and an "all apps" scope.

## 改进

- **浮窗不再时隐时现**：截图时不再把浮窗整个拆掉重建，只是临时设为不可见，截完立即恢复。读页面这类耗时步骤也挪到隐藏之前和恢复之后进行，每次截图浮窗只消失大约半秒，以前要好几秒。进展文字固定占两行高度，浮窗不会因为文字行数变化而跳动。
- **打开 App 就能用**：按“最近用过”的规则自动进入实例：上次用的是远程实例就进远程，否则自动启动并进入本机 OpenChamber 的聊天。以前停留在手机控制页时点桌面图标没有反应，现在也会正常跳转。
- **自动连上手机**：以前打开过手机控制的话，进入本机实例的聊天后，App 会等手机工具准备好，然后在后台自动连接手机，不需要打开手机控制页。从远程实例切回本机时同样会自动连接。无线调试关闭时保持未连接，不弹出错误。
- **授权所有 App**：在“选择应用”里新增“所有 App”开关，打开后包括系统设置、支付、银行、密码类 App 和 AndChamber 自己。开启前需要你确认一个单独的高风险提示。开启后代理能看到可启动 App 的列表；每个任务仍只操作一个 App；系统界面和锁屏仍然不允许操作。
- **系统设置这类会隐藏浮窗的 App**：如果当前任务要操作的 App 会强制隐藏第三方浮窗（例如系统设置），这个任务会自动改用通知栏里的停止入口；通知停止入口不可用时仍然拒绝操作。
- **操作 AndChamber 自己**：可以操作 AndChamber 的首页和聊天页，但打开手机控制页时仍会收回授权。手机控制页正在显示时请求操作 AndChamber，会返回 `PHONE_SCREEN_OPEN`，提示你先离开这个页面再重试。
- **更稳定**：输入法、启动画面这类临时窗口占据焦点时，按“窗口变化”自动重试，不再报 `DRIVER_UNAVAILABLE`。授权被撤回后，读取操作会立即让出，下一次请求不会再误报 `BUSY`；一次失败的启动也不会再把后续请求卡住。

## 验证范围

- 在模拟器（API 35 / x86_64）上用独立测试包、真实浮窗和测试 App 验证：截图时浮窗每次隐藏约 0.2–0.4 秒、过程中从未被拆掉；冷启动自动进入本机聊天，约 40 秒内在后台自动连上手机，全程没有打开手机控制页；“所有 App”下代理能打开系统设置并读屏（通知栏停止入口一直在）；代理能操作 AndChamber 首页，打开手机控制页后授权被收回；手机控制页打开时请求操作 AndChamber 返回 `PHONE_SCREEN_OPEN`。真实浮窗安全测试全部通过。
- 2,147 项 JVM 测试、361 项 Node 测试（360 项通过、1 项原有跳过）、72 项 Python 测试通过，lint 和 debug/AndroidTest 打包通过。
- 还没在真机上复测；验证过程中模拟器本身的图形组件崩溃过几次，属于电脑端模拟器问题，App 没有崩溃。

## Improvements

- **Steady capsule**: capture makes the same window invisible instead of removing and re-adding it, and the slow page reads run before the hide and after the restore, so the capsule is hidden only around the screenshot itself. The running capsule reserves a fixed two-line progress height.
- **Open and use**: launch follows the most recent instance (remote stays remote; otherwise the local chat starts and opens), including from the phone page.
- **Automatic phone reconnect** for a previously configured phone link when the local chat is in front, after this launch's phone tool is ready; silent when wireless debugging is off; never opens the phone page.
- **All apps scope** (opt-in with a separate high-risk confirmation): includes Settings, payment/bank/password apps and AndChamber itself; the model sees the launchable app list; still one app per task; system UI and keyguard stay refused.
- **Targets that hide overlays** (e.g. Settings) switch that task to the verified notification stop entry; otherwise refused.
- **AndChamber as a target** works on Home/chat; the phone-control page still revokes, and a request while it is open returns `PHONE_SCREEN_OPEN`.
- **Robustness**: IME/splash focus is a retryable window change, read-only calls release their slot immediately on revoke, and a failed start no longer leaves a halt that blocks the next request.

## Verification scope

- API 35 / x86_64 emulator with a separate test package, the real overlay and a synthetic target, as described above; real-overlay safety instrumentation passed.
- 2,147 JVM, 361 Node (360 passed plus one existing skip) and 72 Python tests, Android lint and debug/AndroidTest packaging passed.
- Not re-tested on a real phone.
