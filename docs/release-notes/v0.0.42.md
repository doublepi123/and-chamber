# v0.0.42 — 本地部署不再锁定 OpenChamber / OpenCode 版本

> Local deployment no longer pins the OpenChamber and OpenCode versions.

## 改进

- **首次安装和修复都使用 npm `latest`**：本地环境会安装 `@openchamber/web@latest` 和 `@opencode/cli@latest`，不再使用 APK 内置的固定版本。
- **更新不再限制主版本**：更新检查读取 npm `dist-tags.latest`，可以提示跨主版本更新；注册表暂时不可用时，不会再从 APK 内置版本制造更新提示。
- **保留兼容性与版本信息保护**：OpenCode 仍必须不低于 2.0.20，更新提示不会把已安装版本降级，安装后记录从实际软件包读取的版本号。
- **Linux 基础环境不变**：Alpine minirootfs 仍使用固定下载地址并校验 SHA-256；Node.js 等 apk 软件包仍不指定具体版本。

## 验证范围

- 361 项 Node 离线测试中 359 项通过、2 项按既有条件跳过；72 项 Python 离线测试全部通过。
- JVM 测试、Android 构建与签名校验由发布工作流执行；本地环境缺少 JDK/Android 工具链，未在设备上验证最新版本的实际安装。

## Improvements

- **npm `latest` for fresh installs and repairs**: local deployment installs `@openchamber/web@latest` and `@opencode/cli@latest` instead of versions bundled in the APK.
- **No major-version ceiling**: update checks read npm `dist-tags.latest` and can offer a new major version. An unavailable registry no longer produces an update offer from bundled versions.
- **Compatibility and version reporting remain guarded**: OpenCode must still be at least 2.0.20, update offers never downgrade an installed package, and metadata records the version read from the installed package.
- **Unchanged Linux base**: the Alpine minirootfs keeps its pinned URL and SHA-256 verification; Node.js and other apk packages remain unversioned.

## Verification scope

- 361 offline Node tests: 359 passed and 2 skipped under their existing conditions; all 72 offline Python tests passed.
- JVM tests, the Android build and signature verification run in the release workflow. The local environment has no JDK/Android toolchain, and installation of the latest packages was not exercised on a device.
